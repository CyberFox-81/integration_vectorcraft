## Embedding bridge

Started with `?host=parent` inside an iframe, VectorCraft talks to its parent window with `postMessage`. It only accepts messages from the parent window on its own origin, and only sends to that origin. Every message is a plain object with a `type`:

| Message | Direction | Fields | Meaning |
|---|---|---|---|
| `vectorcraft:ready` | VectorCraft → parent | `version` | The app is listening; send a file now. |
| `vectorcraft:open` | parent → VectorCraft | `name`, `bytes` (`ArrayBuffer` or `Uint8Array`) | Open this file, as File › Open would. |
| `vectorcraft:save` | VectorCraft → parent | `name`, `bytes` (transferred `ArrayBuffer`) | A file VectorCraft would otherwise download: Save, Save As or Export. `name` is a file name, or a path the parent picked. The parent stores the file and reports success or failure itself. |
| `vectorcraft:dirty` | VectorCraft → parent | `dirty` (boolean) | Unsaved changes appeared or went away. |
| `vectorcraft:failed` | VectorCraft → parent | `error` | The app couldn't start (for example, no WebGPU or WebGL2). |

With `?host=parent`, what VectorCraft would download goes to the parent instead, and the parent guards leaving the page with unsaved changes. VectorCraft's own Save As dialog still picks the name and format.

Without `?host=parent`, VectorCraft behaves exactly as upstream: saved files download.
